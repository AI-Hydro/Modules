# Static API

Both files are generated by `python scripts/build_api.py` (the same code the `Build Modules API` workflow runs) and are never edited by hand. `python scripts/build_api.py --check` fails when they are stale.

## `modules.json`

An array, one entry per `modules/<id>/manifest.json`, sorted by module id. Every manifest field is passed through, plus:

| Field | Source |
|---|---|
| `moduleId`, `title`, `description`, `version`, `license`, `author`, `topic`, `level`, `estimatedMinutes`, `tags`, `requires`, `citation`, `isFeatured`, `courseId`, `courseOrder` | `manifest.json` |
| `downloadUrl`, `githubUrl` | manifest value, else derived from `moduleId` |
| `createdAt` | manifest value, else the date of the first git commit touching `modules/<id>/` |
| `updatedAt` | **author date of the last git commit that touched `modules/<id>/`** (not the build date; without history it keeps the previous value) |
| `downloadCount`, `githubReactions`, `discussionUrl` | kept from the previous file; reactions are refreshed from GitHub Discussions by the workflow |
| `certification` | see below |

### `certification`

```json
{
  "metadata_complete": true,
  "checks_passed": ["citation", "description", "tags", "estimatedMinutes"],
  "checks_failed": [],
  "scientific_review": null
}
```

- `metadata_complete` — `true` when the manifest has a citation with text, a non-empty description, at least one tag and a positive integer `estimatedMinutes`. **It says nothing about whether the hydrology is correct.** `checks_failed` lists what is missing.
- `scientific_review` — `null` until a human reviewer records a review (reviewer, date, scope); this script never sets it.

The old `certified` / `certified_at` fields are gone: a "certified" badge implied a scientific validity the check never established.

## `courses.json`

An array, one entry per `courses/<dir>/course.json`. Fields: `courseId`, `title`, `abstract`, `version`, `license`, `estimatedHours`, `topic`, `tags`, `trustLevel`, `citation`, `citationUrl`, `isFeatured` and the author fields come from `course.json`; `contributors` is its `authors`; `modules` lists `{moduleId, title, estimatedMinutes, prerequisites?}` in course order; `level` is the common level of the course's modules (`mixed` if they differ); `manifestUrl` and `githubUrl` are derived from the course directory; `updatedAt` is the last git commit touching the course directory.
