1 · What is a watershed?

A watershed (also called a catchment or drainage basin) is the area of land that drains to a single outlet — a stream gauge, a lake, or a river mouth. Every point on land belongs to exactly one watershed.

The outer boundary is the divide: a ridge line along which any raindrop on one side eventually flows one way, and a drop on the other side flows the opposite way. The divide follows the highest topographic points surrounding the catchment.

🏔️
The Divide

A continuous ridge line forming the outer boundary. Defined entirely by topography — extractable from a DEM without any surveying.

Key fact The divide is a line of zero cross-divide slope. Water on the divide is in unstable equilibrium — it could go either way.
🌊
The Outlet

The single point where all water leaving the watershed is measured. Change the outlet location → change the watershed boundary.

Key fact Watersheds are nested: every tributary has its own sub-catchment. They stack like Russian dolls up to the largest basin.

3 · How topography decides where water goes — the D8 algorithm

A computer extracts the watershed by applying one rule to every cell in a DEM: water flows to whichever of the 8 neighbouring cells gives the steepest descent. This is the D8 algorithm (eight-direction flow; O'Callaghan & Mark, 1984).

D8 in 3 steps
  1. Look at 8 neighbours (N, NE, E, SE, S, SW, W, NW).
  2. Find the steepest drop per unit distance — elevation difference divided by the distance to the neighbour (diagonal neighbours are √2 farther).
  3. Fill depressions first (priority-flood), otherwise pits trap the path; then follow the directions downhill to the outlet.
From D8 to watershed All cells whose D8 path passes through your outlet form the watershed. The divide is the outer edge of that set.

Read this scene with care
  • Exaggeration. Heights are stretched 10×. The block-mean heights run from 171 to 556 m across tens of kilometres, so at true scale the surface would look nearly flat.
  • Smoothed. Each mesh cell is the mean of 17 × 17 cells of the 30 m elevation model (510 m), so narrow valleys, peaks and pits are averaged away.
  • Channels are derived, not mapped. A cyan line is drawn where at least 25 km² drain through a 90 m cell under D8 (pysheds 0.5, depressions filled, flats resolved). It is where the elevation model sends water, not a surveyed river. The white path follows the 510 m grid, so it runs near a cyan line, not exactly on it.
  • Lakes are flat. GLO-30 has no slope over water. The build found 9 flat patches of at least 1 km², 110.8 km² in all (about 5 % of the basin). D8 has no gradient there, so a channel drawn across a lake, and the path a drop takes across it, are conventions of the algorithm, not flow measurements. The chip Near-flat steps counts path steps that fall less than 0.5 m on this grid (a slope under 0.1 %): lake surfaces, filled pits and very gentle reaches alike.
  • The edge is the divide. The elevation model was cut to the divide before it reached this lesson, so there is no terrain outside it. The scene is an island: its edge is a drainage divide, not a cliff or a coast.
  • Orientation. Map coordinates are EPSG:5070 (equal-area) metres, with grid north up. True north is about 16.5° to the left of up here.

6 · From rain to runoff — two SYNTHETIC design calculations

The routing above tells you where water goes; these cells estimate how much. Both are textbook design formulas applied to the watershed's area (32 × 32 cells of 30 m = 921 600 m² = 92.16 ha, because every cell drains to the outlet). All inputs are assumptions chosen for teaching, not measurements, and the results are labelled SYNTHETIC in the output.

Rational method — peak flow from a design storm

Q = C · i · A, with runoff coefficient C (–), rainfall intensity i and area A. In SI units with i in mm/h and A in ha this is Q = C · i · A / 360 (m³/s), because 1 mm/h over 1 ha is 10 m³/h = 1/360 m³/s. It assumes a steady, uniform rain lasting at least as long as the catchment's time of concentration, a constant C, and no storage — so it is meant for small catchments. The size limit depends on the agency; check the local design manual.

python Rational method · SYNTHETIC inputs 
import numpy as np
import matplotlib.pyplot as plt

# ─── SYNTHETIC design example: every input is an assumption, not a measurement ───
AREA_HA = 92.16        # 32 x 32 cells of 30 m = 921 600 m² (this module's watershed)
C       = 0.35         # runoff coefficient (dimensionless, assumed)
I_MM_H  = 40.0         # design rainfall intensity (mm/h, assumed)

# Q = C·i·A in base SI units: i in m/s, A in m²
i_ms = I_MM_H / 1000.0 / 3600.0
A_m2 = AREA_HA * 1e4
Q_m3s = C * i_ms * A_m2
Q_check = C * I_MM_H * AREA_HA / 360.0          # the same number from the Q = C i A / 360 shortcut
assert abs(Q_m3s - Q_check) < 1e-9

print("SYNTHETIC rational-method example")
print(f"  A = {AREA_HA} ha ({A_m2:,.0f} m²),  C = {C},  i = {I_MM_H} mm/h")
print(f"  Q = {Q_m3s:.3f} m³/s   (= C·i·A/360 = {Q_check:.3f})")
print("  Valid for: steady uniform rain at least as long as the time of concentration,")
print("  constant C, small catchment. Not a measured flood.")

# sensitivity of Q to intensity for three assumed C values
i_grid = np.linspace(5, 80, 50)
fig, ax = plt.subplots(figsize=(7, 3.6))
for c in (0.2, 0.35, 0.6):
    ax.plot(i_grid, c * i_grid * AREA_HA / 360.0, label=f"C = {c}")
ax.plot([I_MM_H], [Q_m3s], "o", color="#00FFFF")
ax.set(xlabel="rainfall intensity i (mm/h)", ylabel="peak flow Q (m³/s)", title="Rational method (SYNTHETIC inputs)")
ax.legend(); plt.tight_layout()

SCS curve number — runoff depth from storm depth

S = 25400/CN − 254 (mm), initial abstraction Ia = 0.2·S, and for P > Ia the runoff depth is Q = (P − Ia)² / (P − Ia + S), otherwise 0 (USDA-SCS, 1972). CN is an assumed catchment property (soil, cover, wetness); here CN = 75. The two demo storms both exceed Ia, so both produce runoff.

python SCS curve number · SYNTHETIC inputs 
import numpy as np
import matplotlib.pyplot as plt

# ─── SYNTHETIC design example: CN and the storms are assumptions ───
CN = 75
AREA_M2 = 921_600.0                  # this module's watershed (32 x 32 cells of 30 m)
S  = 25400.0 / CN - 254.0            # potential retention, mm
Ia = 0.2 * S                         # initial abstraction, mm

def scs_runoff(P):
    """Runoff depth Q (mm) for storm depth P (mm); zero until P exceeds Ia."""
    P = np.asarray(P, dtype=float)
    x = np.maximum(P - Ia, 0.0)
    return x * x / (x + S)

print(f"CN = {CN}:  S = {S:.1f} mm,  Ia = {Ia:.1f} mm")
for P in (40.0, 80.0):
    Q = float(scs_runoff(P))
    vol = Q / 1000.0 * AREA_M2
    print(f"  storm P = {P:5.1f} mm  ->  runoff Q = {Q:6.2f} mm  (Q/P = {Q/P:.3f}),  volume = {vol:,.0f} m³")

# the curve
P_grid = np.linspace(0, 120, 200)
fig, ax = plt.subplots(figsize=(7, 3.6))
ax.plot(P_grid, scs_runoff(P_grid), color="#00DDFF")
ax.axvline(Ia, color="#f59e0b", ls="--", label=f"Ia = {Ia:.1f} mm")
ax.plot([40, 80], [scs_runoff(40.0), scs_runoff(80.0)], "o", color="#34d399", label="demo storms")
ax.set(xlabel="storm depth P (mm)", ylabel="runoff depth Q (mm)", title="SCS curve number, CN = 75 (SYNTHETIC)")
ax.legend(); plt.tight_layout()
